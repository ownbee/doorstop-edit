# Migrating development setup to uv

This project now uses uv instead of Poetry for Python environment, dependency,
and lockfile management. The package metadata uses PEP 621 in `pyproject.toml`,
with Hatchling as its PEP 517 build backend.

## Developer setup

1. Install uv using the [official installation instructions](https://docs.astral.sh/uv/getting-started/installation/).
2. Install a supported Python (3.11–3.14) if needed, e.g. `uv python install 3.14`.
3. Create/update the project environment: `uv sync`.
4. Generate resources and build metadata: `uv run python build.py`.
5. Start the application with `uv run python -m doorstop_edit`, or run tests
   and tools with `uv run`, for example `uv run pytest`.

**Generation is an explicit prerequisite.** A clean checkout does not contain
`doorstop_edit/ui_gen/` or `doorstop_edit/build_info.py`. `uv sync` installs the
package through Hatchling but does not run `build.py`, and an editable install
does not supply these ignored files. Run the generator command above before
starting the application or running tests. This migration does not add a
packaging build hook: the generator relies on Qt UI tools and build metadata,
so invoking it inside an isolated packaging build would add fragile, implicit
environment requirements. Consequently, the acceptance command
`uv sync --frozen && uv run python -m doorstop_edit` is not sufficient from a
clean checkout; run `uv run python build.py` between those commands. The
direct-command acceptance criterion needs that clarification.

`uv sync --frozen` installs the exact versions recorded in `uv.lock` without
changing the lockfile. Run `uv lock` after intentionally changing
dependencies or project metadata.

## Packaging changes

- The supported interpreter range is Python `>=3.11,<3.15`.
- Runtime dependencies and development tools have been refreshed to stable
  releases compatible with Python 3.11–3.14; exact resolved versions are pinned
  in `uv.lock`. Setuptools is intentionally constrained to `<81` because the
  package still imports `pkg_resources`, which setuptools deprecated and plans
  to remove.
- Hatchling replaces `poetry-core`; its `artifacts` rules explicitly include
  generated UI modules and build information in wheels and sdists despite their
  Git ignore rules. Generate these files with `uv run python build.py` before
  building a distribution; packaging does not generate them automatically.
- `poetry.lock` is replaced by `uv.lock`.
- GitHub Actions test and release workflows now install dependencies, build,
  detect versions, and publish using uv. CI tests Python 3.11–3.14 across
  Ubuntu, macOS 15, and Windows.
- Generated UI modules and build information are still generated by
  `uv run python build.py`; their ignored generated artifacts are not committed.
